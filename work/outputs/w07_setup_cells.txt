## 1. Ranked actions + reason codes

### 1a. Score every page honestly (out-of-fold)

A model that is fitted on a page's own client and then used to score that page looks better than it is (W6 showed this: random-row split gave P@50 1.000 vs 0.852 client-grouped for `y_decline`). So here **every page is scored by a forest that was trained on other clients only**: the same 5 client-grouped folds as W5 and W6.

One difference from W5: W5 scored only pages that have a June label. A real queue must score **all** pages, including those with fewer than 100 June impressions (no `y_low_ctr` label). So each fold's forest is trained on labelled training rows and predicts **all** pages of the held-out clients. For the labelled pages this must reproduce the W5 predictions; the lineage check below tests that.

def make_forest():
    return RandomForestClassifier(n_estimators=300, max_depth=10, min_samples_leaf=50,
                                  class_weight="balanced_subsample", random_state=SEED, n_jobs=-1)

    fold_of[te] = f

        df["p_decline"] = c["p_decline"].to_numpy()
        df["p_low_ctr"] = c["p_low_ctr"].to_numpy()

### 1b. The playbook rule

One action per page, decided by `if / elif` checks **ordered by severity**: the first check that fires wins. The order matters: a page with a suspicious measurement must never reach a "go and edit the page" action.

| # | Action | Fires when | Why |
|---|---|---|---|
| 1 | `verify_data_first` | average position below 1, or zero clicks on 5,000+ March-May impressions | not a real search position / possible tracking gap (seen in W4's top 20) |
| 2 | `verify_then_review` | May impressions far above the page's own history (99th percentile of rises) | more likely a tracking or campaign artifact than real growth |
| 3 | `check_technical_first` | May impressions collapsed by 90% or more versus the page's own monthly average | de-indexing, redirect, URL change or tracking change look the same as a content problem |
| 4 | `monitor_only` | fewer than 5 expected clicks (March-May impressions x the tier's expected CTR) | a CTR gap cannot be measured on so few expected clicks; this removes the low-volume pages that filled the top 20 in an earlier run |
| 5 | `review_ctr_metadata` | W4 reason is `ctr_below_tier_expected` **and** the model's CTR score is in the top 20% | CTR outcome was **stable across folds** in W6 (but partly persistence) |
| 6 | `review_content_refresh` | W4 reason is `slipping_visibility` **and** the model's decline score is in the top 20% | decline outcome was only **directional** in W6 |
| 7 | `monitor_only` | everything else | no strong signal |

**Ranking inside the review queue** is by estimated clicks at stake, not by model score: missed clicks versus the tier's expected CTR for CTR items, lost clicks from the May slip for refresh items. The model score only decides who enters the review pool. This follows a check in W6 (the `ctr_gap_only` vs `missed_clicks` cell): for `y_low_ctr`, ranking by missed clicks gave P@50 0.92 per fold on average against 0.69 for the plain CTR gap. That was one outcome and one K, so it supports the ordering choice but does not prove it.

The thresholds (0.90 collapse, top 20%, 5,000 impressions, 5 expected clicks, 30% client cap) are **policy choices**, not truths. They are named constants so they can be changed and re-run.

# ---- Policy constants (change here, re-run, compare) ----
SLIP_COLLAPSE   = 0.90   # May impressions <= 10% of the page's own Mar-Apr monthly average
HIGH_Q          = 0.80   # "high model score" = top 20% of all eligible pages
ZERO_CLICK_IMP  = 5000   # zero clicks on this many March-May impressions is suspicious
CAPACITY        = 50     # pages a reviewer can handle per cycle (assumption from the lane brief)
CLIENT_CAP      = 0.30   # no client may fill more than 30% of one review queue
MIN_EXPECTED_CLICKS = 5

up = df.loc[df["recent_ratio"] > 1, "recent_ratio"]
spike_threshold = float(up.quantile(0.99)) if len(up) else np.inf   # data-driven: rarest 1% of rises
p_dec_cut = float(df["p_decline"].quantile(HIGH_Q))
p_ctr_cut = float(df["p_low_ctr"].quantile(HIGH_Q))
print(f"spike threshold (99th pct of recent_ratio among rising pages): {spike_threshold:.2f}x its own monthly average")
print(f"model cut-offs (top 20%): p_decline >= {p_dec_cut:.3f} | p_low_ctr >= {p_ctr_cut:.3f}")

def playbook_action(r):
    # ordered by severity: the first match wins
    if r["pos_feat"] < 1:
        return "verify_data_first", "average position below 1 is not a real search position"
    if r["ctr_feat"] == 0 and r["imp_feat"] >= ZERO_CLICK_IMP:
        return "verify_data_first", "zero clicks on a large number of impressions: check tracking before trusting it"
    if r["recent_ratio"] >= spike_threshold:
        return "verify_then_review", "extreme rise versus its own history: likely a tracking or campaign artifact"
    if r["slip"] >= SLIP_COLLAPSE:
        return "check_technical_first", "May impressions collapsed 90%+: rule out de-indexing, redirect, URL or tracking change"
    if r["imp_feat"] * r["tier_expected_ctr"] / 100 < MIN_EXPECTED_CLICKS:
        return "monitor_only", "too few expected clicks to measure a CTR gap"
    if r["reason_code"] == "ctr_below_tier_expected" and r["p_low_ctr"] >= p_ctr_cut:
        return "review_ctr_metadata", "CTR below its tier's expectation and the model ranks it in the top 20%"
    if r["reason_code"] == "slipping_visibility" and r["p_decline"] >= p_dec_cut:
        return "review_content_refresh", "visibility is slipping and the model ranks it in the top 20%"
    return "monitor_only", "no strong signal"

res = df.apply(playbook_action, axis=1, result_type="expand")
df["action"], df["action_why"] = res[0], res[1]

# the model score that matches the reason on the page
df["model_prob"] = np.where(df["reason_code"] == "ctr_below_tier_expected", df["p_low_ctr"], df["p_decline"])
df["evidence_strength"] = df["action"].map({
    "review_ctr_metadata":    "supported: stable across folds in W6, partly persistence of an existing CTR gap",
    "review_content_refresh": "directional only: not stable across folds in W6",
    "check_technical_first":  "data / technical suspicion, not a content finding",
    "verify_then_review":     "data suspicion, not a content finding",
    "verify_data_first":      "data suspicion, not a content finding",
    "monitor_only":           "no action",
})

print()
print(df["action"].value_counts().to_string())

# Ranking: reviews first (by model score), then checks, then monitor
order = {"review_ctr_metadata": 0, "review_content_refresh": 0,
         "check_technical_first": 1, "verify_then_review": 1, "verify_data_first": 1, "monitor_only": 2}
df["action_tier"] = df["action"].map(order)
# estimated clicks at stake, one comparable unit for both review actions
df["missed_clicks"] = (df["imp_feat"] * (df["tier_expected_ctr"] - df["ctr_feat"]) / 100).clip(lower=0)
df["lost_clicks_slip"] = ((df["imp_early"] / 2 - df["imp_may"]).clip(lower=0) * df["tier_expected_ctr"] / 100)
df["opportunity_clicks"] = np.where(df["action"] == "review_content_refresh",
                                    df["lost_clicks_slip"], df["missed_clicks"])
ranked = (df.sort_values(["action_tier", "opportunity_clicks", "imp_feat"], ascending=[True, False, False])
            .reset_index(drop=True))
ranked["playbook_rank"] = ranked.index + 1

def capped_top(frame, n, cap):
    """Take the top n rows in order, but never more than ceil(n * cap) from one client."""
    max_per = int(math.ceil(n * cap))
    counts, keep = {}, []
    for idx, cid in zip(frame.index, frame["client_hash_id"]):
        if counts.get(cid, 0) < max_per:
            keep.append(idx)
            counts[cid] = counts.get(cid, 0) + 1
        if len(keep) == n:
            break
    return frame.loc[keep]

review_pool = ranked[ranked["action_tier"] == 0]
review_uncapped = review_pool.head(CAPACITY)
review_queue = capped_top(review_pool, CAPACITY, CLIENT_CAP)

check_pool = ranked[ranked["action_tier"] == 1].sort_values("imp_feat", ascending=False)   # biggest exposure first
check_queue = capped_top(check_pool, CAPACITY, CLIENT_CAP)

print(f"Review pool: {len(review_pool):,} pages | review queue (capacity {CAPACITY}, client cap {CLIENT_CAP:.0%}): {len(review_queue)} pages")
print(f"Check pool:  {len(check_pool):,} pages | check queue: {len(check_queue)} pages")
for name, q in [("review, uncapped", review_uncapped), ("review, capped", review_queue), ("check, capped", check_queue)]:
    s = q["client_hash_id"].value_counts(normalize=True)
    print(f"  {name:17s}: {q['client_hash_id'].nunique():2d} clients | largest client {s.iloc[0]:.0%}")
print()
print("Review queue by action:")
print(review_queue["action"].value_counts().to_string())

client_share = review_queue["client_hash_id"].value_counts(normalize=True)

def wrong_if(r):
    notes = []
    if r["action"] == "review_ctr_metadata" and r["position_tier"] in ("top_3", "page_1"):
        notes.append("a SERP feature (snippet / AI answer) may be taking the click, so a metadata edit may not help")
    if r["action"] == "review_content_refresh":
        notes.append("the drop may be seasonal or a sibling page absorbed the demand; the decline model is only directional")
    if r["imp_may"] < 150:
        notes.append("close to the volume floor, so a few lucky days can change the picture")
    if r["ctr_feat"] == 0:
        notes.append("zero clicks in 3 months: check the live result page and tracking before editing")
    if client_share.get(r["client_hash_id"], 0) >= 0.25:
        notes.append(f"this client is {client_share[r['client_hash_id']]:.0%} of the queue: possible client-wide cause")
    return " | ".join(notes) if notes else "no red flag in the numbers; still rule out a seasonal drop"

def confidence(r):
    if r["imp_may"] >= 500 and r["days_with_imp_feat"] >= 60:
        return "higher (high volume, steady history)"
    if r["imp_may"] < 100:
        return "low (near the volume floor)"
    return "medium"

for i, (_, r) in enumerate(review_queue.head(20).iterrows(), 1):

### 1d. Did the playbook point at the right pages? (graded on June, after the fact)

Everything below is **measured on pages whose clients the model never saw**. The groups are compared with the base rate (what random picking gives) and with the frozen W4 baseline's top 50. `n_labelled` matters: `y_low_ctr` exists only for pages with 100+ June impressions, so a group can have fewer labelled pages than members.
